## Passe de Security Reviewer

| ataque/erro | defesa comprovada |
|---|---|
| caller entrega objeto “já autenticado” | API recebe mensagem bruta e busca o contexto autenticado em provider confiável interno |
| corpo envia `script`, `command`, `cwd`, env ou token | protocolo estrito recusa campo extra; executor recebe script somente do WorkSpec registrado |
| hash aponta para conteúdo diferente | `WORK_SPEC_NOT_FOUND`; registry clona/congela e calcula hash canônico |
| WorkSpec é reaproveitado em outro target | target faz parte do artefato hashado e mismatch é recusado antes de autoridade/processo |
| contrato/etapa/objetivo stale | manifest é vinculado ao envelope; PRE_DISPATCH exige etapa e objetivo ativos |
| role/skill/capability inexistente, incompatível ou de versão errada | WorkAuthority resolver recusa; processo exige capability `process`, agente exige `agent-runtime` |
| Worker está parado ou dispatcher não foi habilitado | efeito novo recebe `WORKER_NOT_READY`; retry já concluído continua idempotente |
| duas mensagens concorrentes repetem efeito | mesma idempotency key compartilha uma Promise; rebinding de key/dispatch ID é recusado |
| target já possui dono | lock exclusivo recusa antes de criar workspace; lease inclui timeout mais margem de cleanup |
| quota ou budget insuficiente | reserva falha antes de chamar AgentExecutor; nenhuma rota alternativa é escolhida |
| executor declara consumo/custo negativo ou acima da reserva | resultado é recusado e a reserva fecha conservadoramente pelo teto autorizado |
| executor lança erro com detalhe sensível | saída é `executor_boundary_failed`; detalhe original não atravessa fronteira |
| falha após lock/workspace | cleanup tenta remover workspace e liberar lock antes de devolver resultado |
| PowerShell herda perfil, shell ou ambiente secreto | executável absoluto, `-NoProfile`, `-NonInteractive`, `shell:false`, stdin e ambiente explícito com nomes sensíveis recusados |
| saída ilimitada esgota memória | captura possui limite mecânico e mata o processo ao ultrapassá-lo |

## Achados bloqueantes internos e resolução

A revisão adversarial antes da publicação encontrou e resolveu cinco lacunas:

1. readiness do Worker não fazia parte do aceite do efeito;
2. valores de quota/custo do executor podiam chegar ao settlement antes de validação;
3. o target autenticado não fazia parte do WorkSpec hashado;
4. PRE_DISPATCH não recusava etapa/objetivo diferentes do estado vivo;
5. exceção de routing/guard ou lease sem margem podia impedir cleanup confiável.

O candidate `cabc1db` inclui `dispatchAccepted` ligado ao ciclo de vida, validação e settlement conservador, target no WorkSpec, novas cercas de contexto, tratamento sanitizado das fronteiras e margem de lock. Todas as contraprovas foram executadas depois das correções. Resultado: `BLOCKING -> RESOLVED_BEFORE_PUBLISH`.
