## Passe de Security Reviewer

| ataque/erro | defesa comprovada |
|---|---|
| API pública do adapter não oferece CtrlBreak | helper absoluto conecta somente ao console identificado pela sessão, emite evento fechado e se desconecta |
| auxiliar é sequestrado por PATH/cwd/env | PowerShell e scripts internos são resolvidos por caminhos absolutos; helpers recebem cwd confiável e ambiente mínimo sem dados de dispatch |
| processo escapa durante a janela de startup | launcher não libera o target antes de ser atribuído ao Job Object |
| stop imediato ainda libera o comando | gate de saída esperada impede release após transição para stopped; contraprova cobre a corrida |
| erro fatal libera workspace com processo vivo | manager aguarda exit confirmado antes de remover sessão/reserva; teste tenta colisão durante saída atrasada |
| input chega antes do primeiro output | socket de input fixado aceita escrita e backpressure antes de qualquer byte de terminal |
| saída natural perde tail ou deixa worker vivo | exit só fecha depois do flush e um hook interno validado da versão exata descarta o worker residual |
| helper/conteúdo arbitrário é injetado | todos os helpers são internos, argumentos têm conjunto fechado e nenhum shell textual é usado |
| cleanup atinge processos do operador | contenção é exclusivamente pelo Job Object da sessão; nenhuma enumeração global ou por console foi implementada |

## Achados internos e resolução

A revisão adversarial local encontrou e corrigiu sete fronteiras materiais:

1. `node-pty` não oferece CtrlBreak público: foi criado helper cercado e testado com fixture que distingue `ControlC` de `ControlBreak`;
2. a versão `1.1.0` mantém worker de drainage após exit natural: o backend valida a forma interna exata e aplica descarte somente depois do flush;
3. matar processos por enumeração do console seria amplo demais: a solução adotada usa Job Object exclusivo por sessão;
4. helpers poderiam herdar PATH/cwd/segredos: agora usam executáveis/scripts absolutos, cwd confiável e ambiente mínimo;
5. input anterior ao primeiro byte ficava adiado: o canal fixado aceita input imediatamente e respeita drain;
6. stop durante startup ainda poderia liberar o comando: o release agora depende do estado vivo esperado;
7. erro fatal poderia liberar o workspace antes do exit físico: o manager conserva a reserva até confirmação de saída.
